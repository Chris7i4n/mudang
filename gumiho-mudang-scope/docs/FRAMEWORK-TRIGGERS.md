# Framework Triggers

Append-only friction log for new-framework candidates. Format defined in `FRAMEWORK-PLAYBOOK.md` Step 1.

## Format

```
- YYYY-MM-DD | <framework> | <one-line description of friction>
```

Three fields: date, framework name, one-line description.

## Threshold (Path A only)

3+ entries for the same framework within 30 days → candidate moves to `FRAMEWORK-PLAYBOOK.md` Step 2 (evaluation). Fewer than 3 → keep logging; do not act yet.

Frameworks adopted via the **maintainer-asserted path** (`FRAMEWORK-PLAYBOOK.md` Step 1, Path B) skip this log and go directly to Step 2. The path choice is recorded in `FRAMEWORK-DECISIONS.md`.

## Discipline

- **Log honestly.** A one-liner script that solved the problem is not a trigger.
- **Log immediately.** Retrospective logs miss real friction.
- **One trigger per real incident.** Do not pad to justify a framework already wanted.
- **Do not log triggers for frameworks not currently used.** "I might want to use Vue someday" is not a trigger.
